  Formula: price * (expectedBookings > 0 ? expectedBookings : capacity)
  EDGE CASE: expectedBookings = 0 treated same as unset (falls back to capacity)
  Tables:  classes
  Files:   lib/profitability.ts:353-354, form previews
  Dupes:   3

CALC-017: Estimated Final Owner Earning
  Formula: estGross + estSponsorship - estPlatform - estStaffComm - estFixedCosts - estTax
  Tables:  classes, class_staff, class_sponsors
  Files:   lib/profitability.ts:371-380, form previews
  Dupes:   3

CALC-018: Break-Even Booking Count
  Formula:
    netPerBooking = price - platformFeePerBooking - commissionPerBooking - percentageTaxPerBooking
    rawFixedCosts = venueCost + expenses + staffFixed + fixedTax
    fixedCosts = MAX(0, rawFixedCosts - totalSponsorshipAmount)
    IF price <= 0 OR netPerBooking <= 0: breakEven = NULL, achievable = FALSE
    ELSE IF fixedCosts <= 0: breakEven = 0, achievable = TRUE
    ELSE: breakEven = CEIL(fixedCosts / netPerBooking), achievable = TRUE
  NOTE:    Sponsorship offsets fixed costs, can reduce break-even to 0
  Files:   lib/profitability.ts:98-124, form previews
  Dupes:   3

CALC-019: Customer Retention Percentage
  Formula: 100 * repeat_customers / unique_customers
  Tables:  bookings
  Files:   nf0c SQL view: class_customer_retention
  Dupes:   1 (SQL only)

CALC-020: Sponsorship as Break-Even Cost Offset
  Formula: sponsorship reduces rawFixedCosts before break-even division
  DUAL ROLE: Sponsorship also adds to income (CALC-014). This is correct but subtle.
  Files:   lib/profitability.ts:342

SECTION 2: DATA SYNC FLOWS
================================================================================

SYNC-001: Booking Created
  Trigger: Customer submits booking form
  API: /api/bookings/create → book_if_capacity() RPC (atomic)
  Tables Changed: bookings (INSERT), payments (INSERT if paid), classes.booked_count (+1)
  Portals: Customer (email), Owner (on refresh), Admin (on refresh)
  Risk: Medium — no real-time push. AppStore refreshes on mount only.

SYNC-002: Booking Cancelled
  Trigger: Customer cancels or class cancelled
  API: cancel_booking() RPC
  Tables: bookings.booking_status = cancelled, classes.booked_count (-1)
  Portals: Customer, Owner, Admin
  Risk: Medium — on-demand pull

SYNC-003: Class Created / Edited
  Trigger: Owner saves class form
  API: AppStore addClass/updateClass → Supabase direct
  Tables: classes, class_staff (replace all assignments)
  Portals: Owner, Customer (marketplace)
  Risk: Low

SYNC-004: Staff Commission Changed
  Trigger: Owner edits commission in class form
  Tables: class_staff.commission_type, class_staff.commission_value
  Impact: Revenue splits recalculate with new commission on next API call
  Portals: Owner, Staff
  Risk: HIGH — TypeScript + SQL both recalculate. Must verify consistency.

SYNC-005: Staff Payout Recorded
  Trigger: Owner clicks "Mark Paid" in staff page
  API: POST /api/owner/staff-payouts
  Validation: amount <= staffUnpaidBalance (live check)

  Risk: Low

SYNC-006: Sponsor Added to Class

SYNC-007: Currency Rate Changed

SYNC-008: Owner Display Currency Changed

  - money.ts

Added SQL migration:
  - supabase/nf0f-finance-snapshots.sql

Snapshot tables:
  1. booking_financial_snapshots
     Stores booking/payment-time financial values so later margin changes do not rewrite history.

  2. class_financial_snapshots
     Stores current class-level gross revenue, costs, sponsor income, net profit, break-even,
     occupancy, and paid/confirmed booking totals for dashboards and reports.

  3. staff_earning_snapshots
     Stores current staff/class earning amount, paid amount, unpaid amount, payout status,
     commission type/value, and currency.

Recalculation hooks:
  - booking creation
  - class create/edit
  - class cancel/delete
  - expenses create/update/delete
  - sponsor attach/remove
  - staff payout creation
  - explicit POST /api/finance/recalculate/class/[id]
  - explicit POST /api/finance/recalculate/business/[id]

Audit fixes now implemented:
  - platform_margin_percent = 0 is respected
  - money() rounding is shared
  - staff commission formulas centralized
  - break-even and tax previews use the shared engine
  - expectedBookings = 0 remains valid
  - staff_payouts.currency is populated
  - Owner/Staff portals use business operating currency only
  - sponsor income explanation added to create/edit class flows

Rule going forward:
  - Treat lib/finance + snapshot tables as the business calculation source of truth.
  - Treat old SQL views as read-only service-role mirrors/fallbacks.
  - Backfill existing records by running the NF-0F SQL and then POSTing to
    /api/finance/recalculate/business/[businessId].
